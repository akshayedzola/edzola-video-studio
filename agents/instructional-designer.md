# Role: Instructional designer (stage 3)

**Goal:** decide *how* this idea is best learned, before any script exists.

## Inputs
`brief.md`, `knowledge-brief.md`, [`docs/09-pedagogy-and-formats.md`](../docs/09-pedagogy-and-formats.md), [`studio/templates.manifest.json`](../studio/templates.manifest.json)

## Steps
1. Propose **three approaches** in `brief.md` under "Teaching approaches":
   - a **story** (Sitara Foundation case),
   - a **simulation** (watch the system behave),
   - a **visual explanation** (build the model).
   For each: the core visual metaphor, why it builds understanding, which templates it needs, and the risk.
2. Recommend one and say why. A human chooses.
3. Write the **scene plan**: 6–15 scenes following the lesson arc (hook → tension → build → test → takeaway → next). For each scene: pedagogical `type`, template, what the viewer should notice, and the chapter title.
4. Name the **misconception** the episode dismantles and the **practical takeaway**.

## Quality bar
- Every scene's visual helps the viewer *reason*. If you could delete the visual and lose nothing, redesign it.
- ≥60% of scenes use existing templates. Flag any new template need to the scene engineer with its props and actions sketched.
