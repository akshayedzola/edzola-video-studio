# Brief: What is an MIS, really?

| Field | |
|---|---|
| Episode id | x000-revideo-pilot (pilot) |
| Series | A: Technology for Impact, Explained |
| Audience | Nonprofit programme leaders and M&E heads who have bought software but still fight over report numbers |
| The problem they feel | "Every quarterly report starts an argument about whose number is right." |
| Central argument | An MIS is the shared system of record, workflows and reports that makes every team's numbers agree. A dashboard on top of spreadsheets isn't one. |
| Learning outcome | The viewer can explain why disconnected team spreadsheets produce conflicting reports, and what the parts of an MIS are (one record per person → workflows → reports → decisions). |
| Misconception dismantled | "An MIS is a dashboard." |
| Practical takeaway | MAP: model what's worth knowing, align with real work, add AI only on trusted data |
| Format | before_after, with a progressive_construction core |
| Target length | 45–60 s for the technical POC; actual 1:49. Extend to 4–5 min for publication (see below) |

## Teaching approaches considered

1. **Story:** follow Sitara's M&E lead the night before a funder report, reconciling three sheets. Strong empathy, but needs a CharacterScene template we don't have yet.
2. **Simulation:** watch one learner's record drift apart across three team sheets, then see the report numbers disagree. Fully programmatic; the viewer *sees* the cause.
3. **Visual explanation:** define MIS, then diagram its components. Clear but abstract; tells rather than shows.

**Chosen:** simulation (2) for the problem, then visual explanation (3) to build the solution. The viewer earns the definition.
