# MAP framework: Model · Align · Power with AI

**Status:** edzola_opinion (EdZola's own framework, say it as ours)
**Sources:** [map-glossary.md](map-glossary.md), [entity-library.md](entity-library.md), [dashboards-and-kpis.md](dashboards-and-kpis.md), and the EdZola MAP Framework guide.

## The three moves

| Move | One line | The principle to say out loud |
|---|---|---|
| **M: Model** | Decide what's worth knowing. | Every data point must earn its place. |
| **A: Align** | Make the system usable in real work. | If data only flows up, people treat it as compliance. It has to flow back to the people who enter it. |
| **P: Power with AI** | Use AI on trusted data and workflows. | AI is an amplifier, not a purifier. |

The four practical uses of AI under Power: **Collect** (e.g. voice data collection), **Build** (faster system builds), **Work smarter** (assistants inside workflows), **Know faster** (analysis and summaries).

## Where MAP comes from

The ImpactOS lifecycle has six stages, each with a human gate: Discovery → Architecture → Build → Dashboards → Deploy → Maintain. Model ≈ Discovery + Architecture. Align ≈ Architecture through Maintain. Power sits on top.

## Six reasons data systems fail (great series material)

1. **Data collected without purpose.** Built before asking what decision it supports. (Model gap)
2. **Tool chosen before the problem is understood.** (Model gap)
3. **Process confusion gets digitised.** Unclear work just travels faster. (Align gap)
4. **Built for donors, not teams.** Designed for compliance, not frontline decisions. (Align gap)
5. **Go-live treated as the finish line.** No adoption, ownership or iteration. (Align gap)
6. **AI added before the foundation is ready.** It amplifies noise. (Power gap)

## Myth → reality pairs (use with the `Statement` template)

- "We have a data problem" → usually a decision, workflow or adoption problem.
- "More data is better" → every field is a tax on the frontline.
- "Buy a CRM and we're sorted" → a tool over an unclear workflow digitises the confusion.
- "Go-live = done" → adoption starts at go-live.
- "Data is for the donor" → if it only flows up, it's compliance.
- "A dashboard means we're data-driven" → a dashboard without a decision is decoration.

## Definitions that episodes reuse

- **MIS (management information system):** a structured digital platform to collect, store, process and report programme data. A single source of truth connecting registration → activities → outcomes → reporting.
- **Single source of truth:** not one file. An agreement: one definition, one unique ID and one accountable owner per concept.
- **Unique identifier:** one stable ID per record (e.g. BEN-0001) so the same person is never several rows.
- **Dashboard:** a decision view for one audience. Without a decision attached, it is decoration.
- **Theory of Change:** Activities → Outputs → Outcomes → Impact. Activities and outputs are countable; outcomes need follow-up.
- **Leading vs lagging indicator:** attendance is an early signal; income confirms after the fact.
