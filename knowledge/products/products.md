# EdZola products and methods

**Rule:** keep 70–80% of episodes educational. Product episodes (Series C, or a short segment at the end of an explainer) must still teach something. **Every product episode needs sign-off from that product's owner before review** (see CONTRIBUTING).

| Name | What it is | Visual identity |
|---|---|---|
| **ImpactOS** | EdZola's delivery **methodology** for nonprofit data systems: a structured MIS build (usually on Zoho Creator) that runs through MAP, from discovery to go-live and adoption. Always written "ImpactOS". It's a methodology, not a product. | EdZola brand |
| **Zolabs** (zolabs.ai) | Voice AI for qualitative data collection. It turns surveys into natural, multilingual phone conversations and keeps an evidence trail of what people said. | Own brand (violet). Don't use EdZola coral |
| **DozAI** | AI capabilities built on EdZola's expertise (MAP first) that work inside the AI tools teams already use. **Confirm the current product description with the DozAI owner before making any DozAI episode.** | Own brand (paper, ink, signal orange, deep blue). Don't copy EdZola's look |
| **ISOM** (India Skilling Operating Model) | An open operating model for skilling nonprofits: lifecycle stages from mobilisation to post-placement follow-up, with SOPs and a maturity model | EdZola brand |
| ZolaShield | DPDP-compliance infrastructure for nonprofits handling beneficiary and donor data | tbc |
| FundZola | Fundraising management system | tbc |
| edzola.ai | EdZola's self-serve, AI-native platform | tbc |

## Product walkthroughs

Record a **demo tenant with synthetic data only** (Playwright). Never record a real partner's instance, and never show real names, numbers or IDs on screen.

## Pronunciation

Every name above is in `studio/lexicon.json`. Check new names with `npm run say -- "..."`.
